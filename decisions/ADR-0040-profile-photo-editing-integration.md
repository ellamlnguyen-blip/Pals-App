# ADR-0040 Profile photo editing integration

Status: Proposed implementation record. Date2026-10-14. User explicitly requests the interaction scope in TASK-032; publication does not accept new authority, backend architecture or hosted operation.

Preserve current profile UI/private Supabase Storage/profile CAS. Use maintained react-easy-crop6.2.4 for circular/rectangular pointer/touch/keyboard crop interactions; browser produces the selected rendition, existing sharp independently validates actual framing/format and decodes/orients/normalizes it under5MiB input,20MP source and5MiB output caps. Server outputs square primary up to1024×1024 and9:5 extras up to1440×800 (≤1pixel rounding), enforcing aspect independently of client input. Store only new cropped renditions; older originals are not migrated or altered. Reposition of an existing photo starts from its current saved pixels. Reuse immutable upload→CAS reference assignment→guarded detached cleanup and existing owner/authorized peer routes. Reorder only the owned ordered extra-photo references through CAS; no schema/RLS/grant change planned. Invalidation signals carry no identity/photo payload and always re-read current authorized sources.

Alternative hand-built gesture/canvas interaction adds pinch/wheel/focus risk without an existing cropper to extend. The chosen package is a small UI dependency, not a provider or authorization change. New original+crop metadata storage would need a separate privacy/lifecycle decision and is outside this request. Hosted persistence is verified only after Ella's finalization/sign-off on the applicable accepted target, with existing staged acceptance intact.
