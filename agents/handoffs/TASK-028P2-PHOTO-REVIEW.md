### Resolved finding: exact object path could change during URL construction

The original `downloadPeerPhoto` built a URL from `object_path.split('/').map(encodeURIComponent).join('/')`. `encodeURIComponent` leaves `.` and `..` segments unchanged; WHATWG URL parsing normalizes them. For example, resolver metadata `subject-id/../victim/photo.png` became a request for `/profile-photos/victim/photo.png` while both resolver snapshots still bound the original metadata name. Commit `fff9825` adds `privatePeerPhotoUrl`, called when accepting the resolver result and again immediately before fetch. It requires the exact lowercase subject prefix, nonempty safe ASCII segments, allowed extension, no dot/encoded/backslash/query/fragment ambiguity and equality of the constructed URL pathname to the intended path. The production core now passes the verified subject ID into download. A focused regression covers traversal and encoded variants. The URL sent to fetch is now bound to the resolver-returned path on source inspection.

### Resolved finding: self-photo denial became an infrastructure response

In `1350b6c`, `actor_id=subject_id` raised SQLSTATE 42501; the service helper treated all resolver errors as infrastructure failures, so a valid cookie-authenticated self request returned 503 instead of the contract's neutral 404. Commit `1bae785` retains 42501 for invalid original role and malformed resolver input, returns zero resolver rows for self, and short-circuits self at the cookie-authenticated route before service use. The added SQL and core tests check the neutral miss. Actual HTTP self-404 remains a runtime gate.
