## Delivered boundary

- Additive `20260923000600_local_global_blocks.sql` implements ADR-0018's one directional block authority across People, friendship, DM, Hangout discovery/attendance/private detail, roster, group chat, and notification projection. It adds default-off private safety management, minimal Hangout peer provenance, caller-owned ID/state recovery, historical block reconciliation, and a namespaced two-key transaction advisory lock (`16016,1`) before covered mutation locks. Existing People block and outbound-ID RPCs delegate to the safety boundary. RLS and private grants were checked with real `anon` and `authenticated` roles.
- Migration disables every source gate under the shared lock before reconciling an original conflict snapshot. Host-owned blocks remove nonhost targets; nonhost blockers leave; removal wins for a person with both effects. It records overlap before departures, including the departing target's other joined peer relationships. It never restores friendship, DM, or attendance on unblock and does not emit ordinary transition notifications.
- Web temporarily disables every displayed legacy block-write control and both write paths, including stale action/API submissions. Owner ID read and exact unblock remain available when safety is enabled. Active help and confirmation text now states the Hangout effect accurately. No reports, moderation reader, co-host action, hosted migration, or final TASK-016C UI was added.
- Engineering authorization, data model, safety, messaging, and notification docs describe the new boundary and lock order. The earlier TASK-014A People-only limitation is explicitly marked superseded.

## Review focus and limits

Check security-definer search paths/grants, source and safety gate rechecks after contention, sorted parent locks, historical evidence scope (immutable friendship request ledger, terminal DM, host/overlap), no blocked-author pagination oracle, and neutral notification projection. The separate existing photo-delete lock order may safely deadlock and abort a transaction; no partial teardown can commit. The fixtures do not claim to observe every possible overlap between a live read and a committing block; they enforce the documented later-read boundary. The upgrade and race fixtures intentionally require a disposable local database and run serially. Coordinator owns independent review, queue/CURRENT_STATE/CHANGELOG updates, main integration, and TASK-016B dispatch.
