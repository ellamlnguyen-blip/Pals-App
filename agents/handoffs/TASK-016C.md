## Delivered boundary

- A signed-in header entry opens `/safety` for active owners, including onboarding and verification when other sources are unready. The route uses neutral unavailable states for signed-out, restricted, or safety-gate-off owners. It shows only caller-owned outbound blocked account IDs and retained Hangout ID/own-state pairs in 24-row keyset pages. A retained row can report that Hangout or its host without exposing the host ID or hidden Hangout details.
- The new actor-bound, no-store `/api/safety` path validates the current cookie actor marker and versioned global-block confirmation. It calls the existing A/B caller-bound RPCs: `set_safety_block`, `list_people_blocked_ids`, `list_my_retained_hangout_ids`, and `submit_safety_report`. Exact block state is checked through the bounded outbound-ID list; no new raw reader, schema, RLS, service role, or hosted path was added. Old `blockPerson` and `unblockPerson` actions are hard-denied.
- The same block dialog is available from authorized People detail, friend and direct-chat sources. It states host removal and nonhost leaving across all shared Hangouts, including cancelled ones; the loss of friendship/private coordination; no automatic restoration; and no guarantee of physical separation. A direct chat is immediately masked after confirmed block while its result dialog remains usable. The UI disables competing same-surface actions and uses observed exact state after uncertainty; it does not auto-replay an intent or promise transaction cancellation.
- Reports use only existing authorized user, current Hangout, or retained Hangout/host references. Forms enforce the five B categories and trimmed Unicode-code-point narrative limit of 2,000, with a required narrative for Other. A successful submission displays only the opaque receipt/time. A lost response retains the exact UUID and frozen normalized payload in actor-scoped memory for a deliberate same-attempt retry; editing starts a new allegation/key. Narrative is not put in a URL or browser storage.
- Safety client state masks on auth transition, cross-tab safety mutation, tab hide, page restore and actor mismatch; it aborts outstanding reads and checks a generation ticket before post-await display. Owner-list refreshes after same-surface mutations and per-list request sequencing prevent stale page overwrites. No report history, profile lookup, moderator surface, or new target directory was introduced.
