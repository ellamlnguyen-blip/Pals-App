## Memory-only diagnostic interface

`originalSqlDiagnostic(error)` applies only to the exact sanitized Error emitted by `rawSql`; a module-private WeakMap contains a frozen receipt. It accepts no message allowlist. Errors copied/reconstructed by message, raw child errors, arbitrary/nested error objects and transport/signal/spawn/timeout/overflow failures have no receipt. No original message/stderr/SQL/rows/stack/cause/custom field is attached to the emitted error. Later adapters must privately unwrap common neutral wrappers through their separately documented original-error interface, then supply the exact original identity. This prerequisite imports no fixture/common module and creates no cycle.

The public wrapper is unchanged: SQLSTATE and the original six neutral literals retain the existing behavior; every other message remains `operation failed`. The three new source messages stay withheld publicly. The verifier reconstructs the original rawSql function by removing only the private emitted-error recording and checks its exact baseline SHA. This preserves the existing public prefix parser; that parser alone never grants a private receipt.

Private complete grammar, frozen for FULL review:

- Input must be a string of at most64KiB. LF or CRLF physical lines; bare CR fails. Exactly one optional final line terminator. No blank physical lines. At most64 lines and4096 UTF-8 bytes per line.
- The first physical line must match exactly `ERROR:  ([A-Z0-9]{5}): ([^\r\n]+)`: two spaces after `ERROR:`, five uppercase ASCII alphanumeric code characters, colon plus one space, nonempty one-line message. The exact message is never trimmed or extended.
- After it, zero or more opaque recognized records: `DETAIL:  text`, `HINT:  text`, `CONTEXT:  text`, `LOCATION:  text`, in that order, each at most once, with nonempty single-line initial text. Any subset is allowed.
- DETAIL/HINT/CONTEXT can each have at most16 bounded continuation lines. A continuation must begin with ASCII space/tab followed eventually by a nonwhitespace character; it cannot resemble an alphabetic diagnostic label followed by colon. CONTEXT additionally permits unindented `PL/pgSQL function ... line POSITIVE_INTEGER at ...` frames and exact `SQL statement "..."` frames, including nested statements between PL/pgSQL frames. Quoted statement content can span bounded physical continuation lines without indentation; the last quote of its final physical line closes the opaque frame. The quoted content must be nonempty overall. Diagnostic labels, nested SQL/PLpgSQL frame starts or a new auxiliary record while a quote is open fail; an open quote at EOF fails. These lines share the same16-continuation limit per CONTEXT and existing64-line/4096-byte-line/64KiB bounds. LOCATION permits no continuation.
- No continuation is allowed before a recognized auxiliary record. Multiple ERROR, duplicated/reordered auxiliary records, unknown prefixes (including indented/lowercase labels), main-message continuations, trailing unclassified/blank lines, malformed code/framing and limit overflow are unavailable. Auxiliary content remains opaque, is discarded after parsing, and never provides message text.

## Owned HTTP deadline and settlement receipt

Each started request gets its own private AbortController. The existing optional caller AbortSignal—including the unchanged HTTP module's composed signal—is listened to and propagated to that controller alongside the fixed30-second deadline. Already-aborted signal starts no fetch. Invalid signal fails generically. Headers and all streamed body reads share that one30-second deadline. Bytes are counted incrementally; JSON bytes are bounded/parsed only after full consumption, signed bytes are discarded privately. No response.text unbounded consumer remains.

Track original fetch, whole body-consumption and cancel promises by observing their actual fulfillment/rejection. Abort invokes only the owned controller and its owned reader/body cancellation, once. A separate fixed5-second timer bounds settlement observation after abort. A stalled fetch/read/cancel causes a generic failure return and sticky uncertainty; firing a timer or requesting abort never marks a promise settled. Late settlement clears actual pending counts but cannot turn a previously uncertain request into eligible quiescence. Cancel failures and all operation failures stay conservatively disqualified, even if their local promises eventually settle. Successful HTTP business-denial responses (e.g. status400 with valid finite body) are ordinary completed requests, not transport failures.

`quiescence()` observes its private started-request snapshot for at most5 seconds and returns frozen `{available,quiescent,started,settled,pending,failed,uncertain}` counts only. A new request started while receipt observation is in flight invalidates that snapshot. Only an unchanged set whose fetch/body/cancel promises are all actually settled, local operation complete, and no failed/uncertain record yields available/quiescent true. Pending includes requests started during observation. Failure/uncertainty cannot be erased or retried into receipt eligibility; no owner reset method exists. Empty owned request set is locally quiescent. The receipt is private bookkeeping, not a student authorization/result assertion, server settlement, SQL transaction/descendant/PID absence proof or reset permission.

Local event-loop timers do not establish backend quiescence or independently interrupt blocking synchronous guards; unchanged mandatory outer supervision/ownership/cleanup gates remain. The fixed deadline bounds normal asynchronous headers/body work; unavailable settlement returns finite containment only, with no receipt credit. All exact historical success/denial/abort assertions, full54 state deltas, partial child settlement and independently guarded absence remain separate future adapter obligations.
