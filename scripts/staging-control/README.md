# Pals Staging control preparation

This directory contains SQL statements outside automatic migrations. They are prepared for review under Proposed ADR-0029. Do not execute against hosted staging until that design, exact reviewed commit, migration, account evidence, and TASK-027 activation gates are approved.

The runner uses the user's existing logged-in Supabase CLI credential. It calls `projects list` and `db query --project-ref ffabdrgsmtfylrehwmfo` through the Management API; it never asks for a token. It requires `SUPABASE_CLI` only when the installed CLI is not on PATH. Set `PALS_CONTROL_PROJECT_REF=ffabdrgsmtfylrehwmfo`, `PALS_CONTROL_SUBJECT_ID=8ebd74bb-2a72-4689-9580-72268106d91b`, `PALS_CONTROL_REVIEWED_COMMIT` to the independently reviewed full checkout SHA, a fresh `PALS_CONTROL_REQUEST_ID`, `PALS_CONTROL_REASON`, and `PALS_CONTROL_AUTHORIZATION_REF` to the recorded staging change authorization. Choose one `PALS_CONTROL_OPERATION`: `first_manager`, `revoke_manager`, `grant_moderator`, `revoke_moderator`, or `source_gate`.

Manager operations additionally require `PALS_CONTROL_EXPECTED_REVISION` (`0` for first manager; the current live revision for revoke). Source gate operations require `PALS_CONTROL_GATE`, `PALS_CONTROL_EXPECTED_ENABLED`, and `PALS_CONTROL_NEW_ENABLED`, using literal `true`/`false`. The exact source gate allowlist is in `run.mjs`; analytics and large-Hangout safeguards are excluded. `node scripts/staging-control/run.mjs` executes one operation. No bulk toggle is available.

Before each operation, independently verify the live Auth/account UUID, confirmed current email, active UNC campus evidence and expected row state; the SQL repeats those checks under locks for role/manager writes. Verify that the reviewed migration `20261005000100` and current app migration `20261004000100` appear in hosted migration history. The runner checks both versions in the target database, the CLI project list name/ref, `postgres` session, and the reviewed checkout commit before writing. A failed/uncertain response requires read-only audit reconciliation by request UUID. Do not generate a new UUID or retry blindly. The receipt reports the actual shared database session; record the named operator/reviewer in the separate change record.

For local verification only, stream the audit migration to the named disposable local Postgres container, then pipe `node scripts/staging-control/test-local.mjs` to `psql -X -v ON_ERROR_STOP=1`. The test uses an exact synthetic Ella UUID inside one rolled-back transaction. It must never target hosted SQL. Run source gate rollback with expected `true` and desired `false`; revoke moderator and manager separately after shutdown. Availability and capability rollback use Ella's genuine authenticated `set_pilot_policy` session.
