This directory contains SQL statements outside automatic migrations. ADR-0029 is accepted; this admin extension still requires independent review and the actual combined migration preflight. Do not execute against hosted staging until the exact reviewed commit, migration, account evidence, and TASK-027 activation gates are verified.

The runner uses the user's existing logged-in Supabase CLI credential. It calls `projects list` and `db query --linked --project-ref ffabdrgsmtfylrehwmfo` through the Management API; it never asks for a token. The installed CLI rejects `--project-ref` without `--linked` for this query. It requires `SUPABASE_CLI` only when the installed CLI is not on PATH. Set `PALS_CONTROL_PROJECT_REF=ffabdrgsmtfylrehwmfo`, `PALS_CONTROL_SUBJECT_ID=8ebd74bb-2a72-4689-9580-72268106d91b`, `PALS_CONTROL_REVIEWED_COMMIT` to the independently reviewed full checkout SHA, a fresh `PALS_CONTROL_REQUEST_ID`, `PALS_CONTROL_REASON`, and `PALS_CONTROL_AUTHORIZATION_REF` to the recorded staging change authorization. Choose one `PALS_CONTROL_OPERATION`: `first_manager`, `revoke_manager`, `grant_moderator`, `revoke_moderator`, `grant_admin`, `revoke_admin`, or `source_gate`. The role table has one row per account. `grant_admin` requires Ella's current `moderator` role and upgrades it to `admin`, retaining moderation authority under the existing RPC checks. `revoke_admin` restores `moderator` even after account status or email loss. Revoke moderator separately to remove all operator authority. Each transition requires a distinct request UUID and audit receipt.

Manager operations additionally require `PALS_CONTROL_EXPECTED_REVISION` (`0` for first manager; the current live revision for revoke). Source gate operations require `PALS_CONTROL_GATE`, `PALS_CONTROL_EXPECTED_ENABLED`, and `PALS_CONTROL_NEW_ENABLED`, using literal `true`/`false`. The exact source gate allowlist is in `run.mjs`; analytics and large-Hangout safeguards are excluded. `node scripts/staging-control/run.mjs` executes one operation. No bulk toggle is available.

Before each operation, independently verify the live Auth/account UUID, confirmed current email, active UNC campus evidence and expected row state; the SQL repeats those checks under locks for role/manager writes.
