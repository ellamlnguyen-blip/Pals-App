# Pals moderation console

This private operator workspace uses a caller's Supabase session and the publishable key. It runs on the disposable local stack or the exact approved HTTPS staging origin. Production is not enabled by this task. Set `APP_ENV`, `APP_ORIGIN`, `SUPABASE_URL`, `SUPABASE_PROJECT_REF` for staging, and `SUPABASE_PUBLISHABLE_KEY` in the target deployment. The hosted Supabase URL must match the configured project reference. A secret or service-role key is rejected.

On first access, an active operator with a live role enrolls a personal TOTP authenticator and verifies a code. Enrollment is closed by default. For Ella's supervised first setup only, set `ADMIN_MFA_ENROLLMENT_ENABLED=true`, her exact Auth UUID as `ADMIN_MFA_ENROLLMENT_SUBJECT`, and a UTC `ADMIN_MFA_ENROLLMENT_EXPIRES_AT` no more than 24 hours ahead. Close the window immediately after verification and read back the hosted configuration. Factor loss does not reopen enrollment automatically; recovery needs a separate identity/recovery check and reviewed temporary window. Returning operators complete a challenge when their current session is AAL1. A valid AAL2 session can use the workspace until it expires or is revoked; the console does not ask for a new code on each action. The enrollment QR/manual key is private and never stored in browser storage. Ella must personally enroll, retain her authenticator, and participate in recovery verification. No agent should read or retain her TOTP secret.

The server checks the exact request Origin, current account and role, Auth assurance and verified factor before forwarding a report RPC. The database RPCs make the final live session/factor/role decision and retain immutable audits. The UI clears report data on authority loss and rechecks on focus and at a short interval. Each response is private and no-store; hosted Auth cookies are HttpOnly, Secure and SameSite=Lax.

Queue pages contain at most 24 reviewable reports. Opening a detail performs a separate audited read. Every action captures its report, case revision and request UUID before confirmation. If an action response is lost, use **Retry same request** in the same tab; a reload loses that pending request, so open a fresh detail and verify state before any new action. Case actions do not sanction a target. Account suspension/ban/reinstatement and Hangout disable do.

For local work, copy `.env.example` to `.env.local`, supply the disposable local publishable/anon key, start the local Supabase stack and run `pnpm dev:admin`. The moderation gate remains disabled until a local test fixture explicitly enables it. Do not use production as a test target.

The **Launch policy** link opens `/policy` using the same signed-in operator session and authenticator flow. It does not depend on the moderation source gate being open. Only Ella's fixed staging identity with an active account, visible admin role and current AAL2/TOTP session can submit this form; the database's live manager MFA guard makes the final decision. The admin-role read uses the narrow prelaunch own-role policy, which can hide the role if current UNC evidence is lost. The manager RPC itself does not add a per-action UNC check under ADR-0034.

Enter the current revision from the separately reviewed read-only staging preflight, choose one allowlisted gate and desired state, supply a bounded reason and confirm the exact target. The form does not fetch hidden private policy tables or enable gates automatically. External analytics and large-Hangout safeguards are omitted. Enable capabilities before availability, and disable availability first during shutdown. A successful response shows the returned revision and request ID; verify the authoritative state and audit before another change. If the response is uncertain, reconcile the saved request ID before using **Retry exact request**, which sends the same payload and UUID. Sign-out or authority loss clears the form. No service-role key or SQL policy substitute is used.
