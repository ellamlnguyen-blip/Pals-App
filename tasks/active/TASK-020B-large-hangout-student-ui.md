## Integrated A interface

- `public.get_hangout_large_state(p_hangout_id uuid)` returns one row with only `is_large boolean` for a live-ready immutable host while both gates and source authority hold. Denial is neutral `42501`; no row/invalid response must not be treated as `false`. Keep this coarse flag out of ordinary view props, map/list data, logs and analytics.
- `public.query_saved_hangouts(p_west,p_south,p_east,p_north,p_time_filter,p_joining_filter,p_cutoff)` returns JSON `{pins, epoch, ranking_mode}`. `pins` contains at most 101 rows with exactly the current ten `SavedPin` public fields; `ranking_mode` is `small_first` or `chronological`. Capture one cutoff at the start of the server action, pass the same exact timestamp to both calls within A's two-minute bound, call `get_access_state` between them and compare complete ordered `pins`, `epoch` and mode. Release at most 100 items only after a successful match. All other outcomes return no prior items. Do not broaden coordinates, time/join-state filters, output fields or no-store access. A's `docs/engineering/LOCATION_AND_MAPS.md` defines the adapter sequence.
- `public.set_hangout_joining(p_hangout_id,p_expected_revision,p_joining_state)` is the existing host-authorized desired-state writer and returns the next server revision. The action derives the caller session through existing access helpers; it must verify the RPC succeeded and a fresh authorized public/detail read matches **both** returned revision and requested joining state before reporting success.

## Interaction plan

Reading this as: a small safety addition to a map-first student Hangout screen, using Pals' existing white/campus-blue, rounded, Nunito visual language. The live `usepals.com` reference was inspected on 2026-09-25; its bright white canvas, blue feature area and friendly heading weight are cues, while its older navigation and “event” terms are not product authority. Existing `packages/design-tokens/` and saved route components remain the design system. Use a compact caution panel in the saved detail's main column near joining status, above the plan and private instructions, with neutral clear copy rather than an alarm badge or public count. The current host sees the exact accepted warning only after a fresh authorized `large=true`: “This Hangout has a large group. Check that the meeting place works for everyone. You can close joining while you coordinate.” No warning/count/badge appears for other viewers or on map pins. A lower-than-threshold result removes the warning on the next refresh without an animation implying live monitoring.

The host sees “Joining open” or “Joining closed” and one 44px minimum target labeled “Close joining” or “Reopen joining” for the desired next state. Text explains that closing keeps current members joined. A click disables the control and sends one expected-revision request. Claim success only when the RPC succeeds with its returned revision **and** a fresh caller-authorized read matches that revision and desired joining state. Another actor arriving at the desired state, a lost response, stale revision, permission loss or conflicting state cannot be called this action's success. The UI shows a neutral reload-needed message with no blind second toggle or optimistic success. On access loss, immediately mask warning, control, source detail and private instructions in the mounted client surface before a hard navigation/reload; do not leave old protected content behind while `router.refresh()` is pending. Keep keyboard focus sensible after save or failure and announce a short status. On phone the panel and button stack without horizontal overflow; on desktop it sits within the existing content grid. Reuse shared tokens and CSS; no new library, decorative animation or shared token overhaul.

The saved map/list keeps its existing filters, map viewport, matching list, no-token fallback, marker/preview/detail behavior and superseded-response suppression. Its backend query calls A's RPC twice with identical bounds/filters/cutoff around a fresh access-state check, compares the full ordered 101 rows, ranking mode and gate epoch, and returns no prior items on mismatch/denial. Truncate at 100 only after the second comparison. For `small_first`, explain “Showing up to 100 Hangouts in this area. Smaller groups appear first. Zoom in or narrow the filters to see more.” For `chronological`, retain the existing truthful start-time/limit copy. A's reviewed `ranking_mode` field, never order inference or an opaque epoch, determines the copy. Do not expose a size class, count or popularity badge. No ranking claim is made for Calendar. Never promote hidden private fields into preview/analytics.

Loading, empty, error, denied, discovery gate-off, stale and uncertain states must be distinct. A failed host-size RPC cannot become `false` silently and cannot identify gate-off versus another denial; show a generic unavailable status and withhold the warning, while the accepted existing host joining authority remains available if independently reauthorized. A failed discovery RPC never falls back to a reader with a broader or stale result. Keep the detail's existing final public/private/source rechecks and source-gated no-store behavior. No new PostHog event or property.
