## Allowed implementation
- Add an additive committed migration, with a Hangout-scoped co-host assignment bound to existing participant identity. Only a current joined, live-ready, same-campus assignment grants effective co-host authority on a published, undisabled Hangout. Host is immutable and never co-host. A lost readiness state suspends authority; if the still-joined retained assignment regains readiness it becomes effective again. Leave, host removal and safety block teardown must clear the assignment atomically. Cancellation makes assignments ineffective; existing nonhost leave and host removal after cancellation remain permitted and clear any assignment. A removed/left member who later rejoins gains no role automatically.
- Host-only promote an existing live-ready joined nonhost; host-only demote an assigned target even after target readiness loss; co-host self step-down retains joined membership. Co-hosts may edit accepted public/private details, open/close joining and remove a current-ready joined ordinary member only. Co-hosts cannot cancel, assign/demote roles, remove a host/other co-host or inspect nonready/historical membership. Host retains cancellation and removal of joined/left nonhosts, including nonready targets and cancelled Hangouts. Target checks use authoritative state, never supplied role claims or a roster snapshot.
- Expose only host/co-host/participant labels alongside account IDs already permitted by current-ready roster RLS. Add a separate bounded, complete host-only current-assignment reader on a published Hangout that includes nonready assigned IDs for revocation. It returns no names, photos, historical assignments, block relations, private location or moderation state. Keep existing owner-only peer profile/photo policy. Design pagination with a stable cursor so a host can reach every retained assignment without an unbounded response; fail closed under gate/readiness/host block/disable changes.
- Preserve caller-bound fixed-search-path operations, denied direct table DML, `READ COMMITTED` only, and the current global lock order: `private.social_hangout_mutation_lock()` before Hangout parent row, then source/identity/role evidence, participant/provenance writes, then notification gates and recipient locks. Recheck actor and target authority after every lock wait. The existing `private.lock_hangout` enforces live campus/gate and moderation disable; never bypass it for a management operation. Block teardown/reconciliation updates participants directly and therefore must clear assignments through a sound central invariant or equivalent complete transition coverage; retain `private.safety_record_joined_overlap` before host removal/leave. Block/unblock cannot restore a cleared role.
- Role changes and management removals require the expected Hangout revision and advance it on success. Replace/revoke/drop the old executable `remove_hangout_participant(uuid,uuid)` signature; no legacy overload may bypass revision checks. Update every repository SQL/HTTP/concurrency consumer and confirm old signature denies direct RPC calls. Ordinary leave stays revision-free; when it clears an assignment, advance the management revision under the same parent lock. For allowed host removal/nonhost leave after cancellation, the current ownership trigger rejects every distinct cancelled-row update. An additive replacement may permit only `revision = old.revision + 1` with every other Hangout field, including `updated_at`, unchanged; the participant and assignment changes occur in the same transaction. This preserves terminal cancellation and the attendance RPCs’ current pre-start-cancellation test based on the original `updated_at`. Never stamp `updated_at` after cancellation, or a pre-start cancellation could become answerable after a later removal/leave. Test pre-start cancel, wait/cross start, then host removal and nonhost leave: attendance must remain denied. If another safe design is needed, surface it for review before code. No public/private detail edit or reopening.
- Preserve existing atomic public/private edit, create retry, join block-precedence/overlap provenance, and notification semantics. A material co-host edit emits only the existing `hangout_edited` event; host cancellation emits only existing `hangout_cancelled`; existing join/leave events stay idempotent and subject to notification gates. No new co-host event, inbox type, recipient class or analytics event in this stage. Safety-forced teardown emits no ordinary departure event. Co-host edit actor ID must not be interpreted as host ownership.
- Retain the database attendance schedule freeze after its opening boundary, even for co-host edits and when attendance gate is off. No attendance answer reader or alteration. Existing TASK-020 host-only coarse size flag stays host-only; co-hosts get no count, threshold flag or private signal access. Co-host joining control uses current `set_hangout_joining` semantics: voluntary open/close, no eviction, capacity or automatic threshold action. Preserve saved-discovery dampening and private unconsumed size signal on genuine joins.
