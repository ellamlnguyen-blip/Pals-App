## Goal and exact boundary

Build the student-web-only, default-off analytics foundation for disposable-local testing: typed event allowlist, minimal PostHog-compatible capture envelope to an explicit loopback test sink, memory-only consent, and a small accessible choice in the account area. Do not wire any product event in A. Stage B will consume the reviewed adapter and owns all product event call sites.

## Implementation contract

1. Implement one browser-only adapter with a compile-time list of the 14 parent event names and a runtime validator that rejects unknown names and caller-supplied properties before transport, including values smuggled through TypeScript casts or JavaScript callers. The adapter itself creates exactly one application property, `schema_version: 1`, and the provider control `$process_person_profile: false` required to avoid person processing. It may use a minimal direct PostHog-compatible capture transport instead of a general SDK if that is the cleanest way to meet ADR-0023. Do not add a second provider or a data-access abstraction. A local test sink/transport injection must make the full outbound request inspectable without external ingest. No app event call sites in A.
2. Capture is disabled unless the **raw** `APP_ENV` string is literally `local` (not its defaulted parser result), a strictly validated loopback sink and nonsecret local project token are explicitly configured, the current tab has affirmative consent, and current authenticated account state is confirmed as onboarding or ready. Use a no-store, owner-authorized local access check (or equally authoritative server bridge) to establish the consented account ID in memory and compare it again immediately before every capture; do not put the ID in storage or the analytics request. Check the same tab generation again after the access response and before sending. A missing/invalid config, uncertain or mismatched auth state, lost access or hosted environment remains off. On focus, pageshow and auth transition, pause capture immediately and recheck current identity; resume the same tab's choice only after confirming the same account, and clear it on mismatch, sign-out or denial. Do not assume a broadcast proves identity. Do not initialize an SDK, connect or queue before consent. Validate the raw sink URL before URL normalization: accept only canonical `127.0.0.1` or `[::1]` HTTP origins with an explicit port and fixed capture path; reject userinfo, alternate numeric/hex/octal loopback forms, extra path/query/fragment and redirects. Send with `redirect: 'error'`, `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`. Hosted PostHog hostnames must be rejected in this stage.
3. Consent starts off in every tab and after reload. Keep it only in memory. The account-area control explains the event categories, including that a Hangout chat send and first DM request may be counted while message contents and recipients are excluded. It also explains that attendance/safety activity and identifying details are excluded, the current-tab/reload limit, and how to turn capture off. The opt-in and off controls are keyboard-accessible and show the current state without a dark pattern. A signed-in onboarding student can reach the choice so `onboarding_completed` is possible in Stage B. Restricted/signed-out states cannot turn it on.
4. On revocation, sign-out, account switch, uncertain revalidation or another tab's revoke/sign-out, stop new captures immediately, clear pending work/provider state and rotate the random visit ID. Reuse the existing auth transition broadcast pattern without making another persistent identifier. Other tabs do not inherit opt-in. A transient capture failure has no effect on product actions and creates no local retry queue, cookie or event log.
5. The outbound request must carry only the provider-required event envelope, an unrelated random visit `distinct_id`, `schema_version: 1` and `$process_person_profile: false`; test the full URL, headers, query string and body for account/source IDs, URL/referrer, geolocation, application-added user agent properties and SDK-added fields. Browser-added transport headers and IP are unavoidable on direct requests and are a separate hosted-release issue. No `identify`, `alias`, person/group profile, automatic capture, replay, heatmap, form/error capture or private-event API is exposed. The local sink is synthetic and does not save requests outside the test process.
6. Put the consent entry under the existing avatar/account area. Keep existing five primary destinations. Use existing visual tokens/components, no new design system or global restyle. Add only the necessary account-area and consent-page styles. If a route needs a local-only guard, reuse repository access conventions and return a neutral off/disabled state on failure.

## Acceptance gates

- Focused adapter/transport tests prove compile-time and runtime event name/property rejection, including cast/JavaScript bypasses, disabled default, no pre-consent capture request, opt-in, off/reload, concurrent tabs, auth begin/settled/cancelled/revalidate, sign-out/account switch including an unsignaled cookie change, focus/pageshow pause and same-account resume, denied/uncertain auth, stale in-flight access response, blocked sink, transport error and no retry/backfill. Test raw environment unset/nonlocal, alternate loopback forms, URL contamination and redirects. The capture transport cannot be called with arbitrary strings or properties by other modules.
- Local sink inspection proves no forbidden field in actual requests. The sink receives zero requests for all off states. Local-only and hosted-target rejection are tested.
- Rendered desktop/phone, light/dark and keyboard checks cover the account entry, initial off, opt-in, off, reload, denied/uncertain state and error feedback. `pnpm check` and any focused auth regression pass within recorded limits.
- No database migration, feature-gate change, hosted target, external ingest, product event wiring or admin/mobile code. End with zero fixtures, nine product gates false and owned services stopped. Produce an evidence-based handoff and task branch. A fresh exact-tip privacy/security/design review and verified main integration precede B dispatch.
