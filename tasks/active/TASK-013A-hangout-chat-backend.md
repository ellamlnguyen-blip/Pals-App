## Allowed scope
- Add one committed additive local migration after current migrations. Bind one conversation to each saved Hangout, created atomically on first authorized send, with an empty authorized read before it exists. Store immutable plain-text messages, server-owned IDs/author/time, monotonic per-Hangout ordering and a private caller/Hangout/key creation ledger. Add a separate default-disabled private chat gate. Apply RLS and explicit revokes to every new table; no direct authenticated/anon table access or platform-role bypass.
- Add fixed-search-path caller-bound send and keyset-page read RPCs. Derive actor from `auth.uid()`, never from a supplied author/campus/recipient. Accept trimmed text of 1–2000 characters and one UUID creation key per composed message; exact currently authorized retry returns its original message, changed-payload key reuse fails and revoked retry never returns prior content or creates a new message. Cap each page at 50 with stable ordering and validated cursor/limit. Avoid generic count or message-existence oracles for unauthorized callers.
- Require both local gates, READ COMMITTED, current ready same-campus joined membership and published campus Hangout for every read/send. Send uses the same Hangout-row serialization semantics as `private.lock_hangout()` for join/leave/remove/cancel, then transaction-held locks on both gate rows and all caller readiness evidence (`public.accounts`, `auth.users`, membership/campus, profile and referenced primary photo object), using one documented deterministic order. Lock modes must conflict with updates/deletes of those rows: use `FOR SHARE` or stronger for mutable rows; `FOR KEY SHARE` alone is insufficient for status/email/verification/completeness/path updates. Recheck in a fresh READ COMMITTED statement after waiting. A committed revocation first denies; a send that commits first is visible only to later authorized reads. Do not weaken existing Hangout operations/RLS. A read uses a fresh authorization check in the same statement as page projection; document and test the accepted in-flight read limitation.
- Return body/time/order/`mine`; return an author ID only if that author is currently ready and joined in the Hangout, otherwise a neutral former-participant label with no ID. No raw peer profile/photo, email, historical author ID or extra relationship fields. Current authorized late joiners/rejoiners can page all retained history. Left/removed members and all clients after cancellation cannot read any history; rows remain private for later safety work.
- Add meaningful actual-role SQL/pgTAP, real caller-session Auth/PostgREST and deterministic overlapping-session tests. Update only relevant backend/API/test documentation. No web route, UI, notification, Realtime, hosted change or moderation access in A.

## Hard invariants and edge cases
- Both gates default false after reset; friendship/People gates and blocks do not confer or revoke chat access under this accepted local policy. No client table grants, direct DML, raw-message subscriptions, service-role app path or admin bypass. Stronger isolation fails closed.
- Author projection is evaluated at read time, including after author leave/removal/readiness loss. An authorized late join can see pre-join content; a permitted rejoin can see messages from their absence. Removed users cannot rejoin under ADR-0010. Cancellation makes all client chat reads/sends unavailable without deleting retained records.
- Concurrent duplicate sends of one creation key commit at most one immutable message. Exact retry is authorized anew; conflicting payload/key reuse does not mutate. Pagination is deterministic under concurrent inserts, no duplicate/skip at page boundaries. Preserve current Hangout private-location and roster authorization; no new peer-profile reader.
- Physical content may have been delivered before revocation and an already authorized read can complete after it. New authorization statements after committed revocation deny. Do not claim that previously delivered content can be recalled.
