## Goal and authority

Implement only ADR-0019's moderated Hangout disable and its source-wide student access effect. An authorized operator acts on the exact stored `hangout` report target in an `in_review` case. One new action atomically disables that Hangout, closes the case as linked `action_taken`, stores an immutable private action and audit, and records an idempotent result. The moderation gate and all existing source gates remain default off. This is disposable local work; TASK-017C separately owns the admin UI. No re-enable action is accepted.

## Action and evidence boundary

- Add one narrow authenticated caller-bound RPC, for example `apply_hangout_moderation_action(report_id, request_id, expected_case_revision, reason)`, whose only new action is `disable`. Derive the live actor from `auth.uid()` and Stage A's default-off moderation gate, active account, platform moderator/admin role and report conflicts. Require READ COMMITTED, exact stored target type `hangout`, an existing target, current `in_review` case and expected revision. No separate Hangout ID, host ID, campus, role or status claim is accepted. The reporting operator, target Hangout's current host, unknown/inaccessible ID, gate-off actor and stale action receive neutral denial. Never infer a user sanction from a Hangout report.
- Represent moderation disable separately from Hangout lifecycle cancellation. Preserve the public Hangout's `published`/`cancelled` lifecycle, immutable host/campus and retained participation/evidence. A private one-way disable record keyed by the exact Hangout is the preferred shape; an equivalent representation must maintain all these invariants and work for a cancelled Hangout. No client table grant, broad reader or re-enable RPC. A newly accepted disable closes its own case with `action_taken` and advances revision once. A Hangout already disabled by a different report cannot produce another disable action or fake a new `action_taken` finding. Reopening a closed case clears only its current action link/disposition, never the historical disable or audit.
- Extend the Stage A/B1 case schema so `action_taken` has **exactly one** linked committed account sanction or Hangout disable of the same report and target type. Persist the exact report/Hangout/operator, required trimmed 1–2000-code-point reason, server request/time, prior/new moderation-disabled state and authoritative current Hangout campus. Append one immutable private audit event containing that action link, actor, exact subject/campus, previous/new case state and revision, and no allegation narrative, public/private place, precise location, profile, photo or message. Action, case closure, request result and audit commit atomically or all roll back. Keep restrictive references and existing append-only evidence; no deletion API.
- Use the shared operator-scoped request UUID identity across Stage A case actions, B1 account actions and B2 disable. Exact same-payload replay first passes the current moderation gate, active actor/role, report conflicts and target availability, then returns only the saved minimal result without a second disable/revision/audit. Changed-payload or cross-RPC key reuse fails neutrally. A replay after role/account/gate revocation or a new self-host conflict denies. Return only minimal case state/revision and disabled state, with no raw audit or hidden target lookup.
- Extend the already audited exact-ID operator report detail by only a server-derived nullable `target_disabled` boolean for Hangout targets. Keep `target_status` as its current lifecycle and `target_campus_id` as current campus; an unavailable target keeps `unavailable` context and null disabled value. Preserve all Stage A/B1 queue/detail allowlists, access audit and conflict checks; queue and student APIs gain no disabled-state reader.

## Student enforcement matrix

- After a committed disable, current and future students, including the host and joined attendees, must lose the Hangout's public/detail/roster reads, map pins, Calendar entries, private instructions and group-chat reads/sends. Notification rows pointing to it project the existing neutral unavailable state and offer no usable destination. Joining, leaving, attendee removal, editing, joining-state changes, cancellation, chat send and any current host/co-host management path must deny. Existing direct REST table reads/embeds and old RPC signatures must enforce the same source rule, not merely the web UI.
- The accepted safety exception survives: an active caller can recover only their own retained Hangout ID and participation state under the safety gate, and can file the existing private user/Hangout/host report when their retained evidence qualifies. Do not reveal disabled Hangout title, location, host, roster or chat through this route. Preserve existing block/reconciliation evidence, immutable host ownership, separate terminal cancellation, and no ordinary source notification for moderation disable. The disable retains reports, participants, messages and private locations as private evidence rather than erasing them.
- Use this documented order for a new disable: shared TASK-016 social/Hangout mutation advisory lock, Stage A moderation advisory lock/gate/actor account and role, stored report, target Hangout parent lock through commit, operator request UUID, case and writes. Acquire the target parent `FOR UPDATE` once after reading the stored report; reproduce Stage A's conflict checks under that lock rather than first taking its helper's `FOR SHARE` Hangout lock and upgrading later. The shared lock must precede the Hangout parent, matching existing student writers; freshly recheck gate, role, report conflict and target after every wait. Student writers already holding the parent may commit first; a disable that gets the parent first makes later writers wait, freshly recheck the disabled state and deny. A read already in flight may finish; a later direct table/RPC/API read after commit must be masked. Test both observed commit orders for edit/join/chat/cancel and any other distinct writer lock path. Do not weaken source gate, block or account-status checks.
