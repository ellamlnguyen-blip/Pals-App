## Implementation contract

Create private account-UUID roster with active/revoked state, monotonic revision and server times; private singleton pilot availability default false and fixed capability keys `onboarding`, `hangouts`, `hangout_chat`, `calendar`, `people`, `friendship`, `dm`, `notifications`, `attendance`, `optional_profile`, `extra_photos`, `analytics`, `large_hangout_safeguards`, each default false; independent safety/moderation gates are retained outside ordinary pilot shutdown; separate private active/revoked/revisioned admission-manager authority; immutable private admission/policy audit and caller-scoped idempotency ledger. All private relations have RLS and explicit public/anon/authenticated revokes; no client SELECT/DML, roster listing, email resolver or arbitrary-subject status RPC. No backfill of admission or managers from existing users/platform roles/metadata. Missing records deny; future public mode is excluded.

Expose `public.set_pilot_account_admission` and `public.set_pilot_policy` (exact typed signatures documented in migration/test inventory) as narrowly authenticated manager RPCs for target UUID activation/revocation/reactivation and allowed policy/capability desired state. Derive actor only from auth.uid(), fixed empty search path, fully qualified references, operation/state/key allowlists. Inputs limited to target where needed, desired allowed state, expected revision, bounded nonblank reason, caller-scoped request UUID; no actor/email/arbitrary SQL/manager assignment/platform-role input. Expected revision is required: absent target/config key has revision `0`, first insertion revision `1`, each actual change increments once; existing same desired state is an authorized no-op with unchanged revision, one immutable successful-operation audit/receipt and no secondary effects. Exact retry appends no audit. Revision mismatch fails atomically; no silent upsert ignoring CAS. Policy singleton is seeded off at revision `1`; capability records are seeded off at revision `1`; if a seeded singleton is absent, policy mutation fails closed rather than silently recreating it. Account/manager state allowlist is `active|revoked`; availability/capability values are booleans; unknown keys/malformed reasons fail. Reasons are trimmed nonblank 1–2000 Unicode characters, with existing profile trim semantics. Activation checks live exact-domain confirmed current UNC evidence/active campus/account without profile/photo readiness; revocation remains possible after verification loss. Separate manager live active-account/authority is required, independent of student verification/admission/pilot policy.

Exact authorized retry returns only original minimal management receipt/revision after current manager/account authorization. Fingerprint covers operation/target/desired value/expected revision/reason; changed payload/cross-operation/different-actor reuse never returns another receipt. Successful changes atomically append actual actor, target as applicable, old/new state, revision, reason, request UUID and server time. Denied/stale/failed transactions produce no partial mutation or success audit. Test the defined normalized no-op/identical desired-state audit/idempotency behavior without inventing broad source reads. Capability policy uses the fixed key allowlist; it never grants admission/verification/roles or bypasses existing source gates. Normal pilot configuration enables only retained core keys; isolated historical regression fixtures explicitly activate needed deferred keys temporarily and reset them, without adding a nonpilot mode.

Provide narrowly private privileged bootstrap/manager-change mechanism or fixture-only trusted path with attributable actual local executor identity, immutable audit provenance and explicit no client EXECUTE/DML. No arbitrary actor string substitutes for authenticated administrative provenance. Hosted bootstrap procedure/roles excluded. Synthetic fixture setup may create/revoke managers and needs separate audit evidence; manager RPC cannot self-assign/revoke managers or mint moderation authority.

Write and independently review exact lock graph before implementation: existing `private.social_hangout_mutation_lock()` first for management boundary, deterministic policy/manager/target evidence locks, sorted UUID evidence, live post-wait authorization and locks through commit. Do not introduce opposite order to source writers in A1b. Missing roster/manager/policy rows require a common transaction/advisory serialization key used by trusted fixture writer too; nonexistent row locks are insufficient. Account/platform moderation and trusted manager revocation races must be considered; READ COMMITTED fresh checks, existing stronger-isolation denial preserved. Shared global advisory lock alone is insufficient for existing direct profile/Storage writes: A1b must use the new evidence lock contract after their row locks without deadlocking silently. Safe abort is acceptable where documented, stale authorization is not.
