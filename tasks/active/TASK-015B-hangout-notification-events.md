## Allowed work
- Extend the private notification ledger's constrained source kinds/event codes, category mapping and current-source projection for these events only: material Hangout detail update (`hangout_updates`), Hangout cancellation (essential, not muted), actual join/leave to current host (`host_activity`), and saved Hangout-chat message to current joined participants other than sender (`messages`). Detect a material edit only after both the public Hangout update and private-instruction upsert/delete finish, comparing normalized old/new public and private values; a revision-only identical edit creates no item. An open/close-joining change, removal, create, retry or no-op join creates no item. Never store message body, old/new detail, private instruction, location, roster snapshot, profile data or arbitrary URL.
- Generate rows in the authoritative mutation transaction only, after existing Hangout parent-row and readiness/gate locks, and only when the notification gate is enabled. A failed/stale mutation creates none. A gate off or optional-category mute does not veto the source action and is not backfilled. Cancellation delivers to joined participants even when `hangout_updates` is muted. Source/notification gate disable and preference changes obey the TASK-015A gate `FOR SHARE` → recipient advisory order and fresh check; fan-out locks recipients in deterministic UUID order. Preserve the existing source operation signatures, grants, gate behavior and isolation requirements.
- Use one server-owned event identity per actual committed transition, shared by all recipients of that transition, plus recipient uniqueness. For Hangout/chat messages, use the immutable server message ID; for edit/cancel/join/leave, use a server-generated event ID or a proven unique immutable source transition identity, not a client request ID or wall-clock timestamp. A new join after a leave is a new event; exact retries/no-ops do not duplicate. Adapt TASK-015A's constrained ledger and uniqueness without weakening its friendship/DM identity or private retention.
- Select recipients from current joined participants at event time, excluding the actor; for join/leave, select only the actual current host (who must not receive a self-event). Do not notify a former participant or inferred friend. Reader projections are per event code: an edit requires the recipient's **current joined membership** as well as live ready campus/Hangout gate, even though a published public Hangout remains readable after leaving; cancellation requires current joined membership and the existing cancelled-view authorization; host activity requires the recipient to be the current ready host and returns no attendee actor ID; chat requires current `chat_authorized` membership and both source gates. Return the source-specific code, target ID and link eligibility only when that exact check succeeds. A revoked/removed/cross-campus/unready/gate-disabled source becomes the same neutral unavailable form as TASK-015A. Host join/leave items use generic wording with no participant actor ID or count, even though the host may have separate member-state tools; this avoids departed-roster disclosure.
- Add actual-role SQL and real local Auth/PostgREST tests for all event types; private instruction null→value, value→null and normalized-equal/no-op edits after the complete RPC plus failed/stale edit; cancellation with muted updates; joined-only fan-out and leave/remove neutralization of old edit items; no host self-notice; join→leave→rejoin identity; no notification from removal/open-close; direct table/forged source denial; revoked reader projection; gate/mute races and observed Hangout parent-row lock races for leave/removal versus edit/chat send and cancellation versus send, checking recipients and absence of post-revocation items; cursor stability mixed with A's social items; exact chat retry; and surviving A friendship/DM behavior. Run two clean resets, full database suites, lint and workspace checks. Keep gates false, synthetic fixtures cleared and services stopped after tests. Update relevant engineering docs and write a bounded handoff.
