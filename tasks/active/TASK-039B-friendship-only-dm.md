# TASK-039B — Friendship-only DM server authorization

Status: ready for bounded disposable-local server implementation. Ella explicitly accepted ADR-0045 on 2026-10-16, including private retirement of existing request-only/nonfriend generations. Its previous accepted predecessor ADR-0042 permitted accepted message requests independently of friendship. Start after this accepted-policy contract is published on canonical main, from current `origin/main` plus exact reviewed 039A source `98327d14d6b35f333ed4afe64ac663427ca0bd5c`.

Implement additive committed migrations on the named disposable local database only. Cover every caller-bound DM function, retry, list/thread read, combined chat attention, notification source/destination, friend teardown and safety block. Retire pending/request-only generations without deleting evidence; preserve accepted-friend conversations only while friendship is current. Replace or revoke old callable request and independent-consent paths so a stale client cannot bypass the new policy. Existing web routes are an untrusted caller until 039C changes them; test direct RPC denial from old route inputs. Keep web/UI and Hangout chat/co-host behavior outside 039B scope.

Require source and migration review, two-account authenticated SQL/RPC allow/deny flows, RLS/grant and concurrency/retry tests (including legacy directional suppression and close/refriend transitions), and notification neutrality checks. A fresh security reviewer must inspect the exact migration tip and report findings before 039C depends on it. Record exact branch, migration and named disposable database state in the handoff. Local verification is a milestone, not final task completion: accepted-environment persistence, predecessor sign-off and reviewed application-main integration remain separate gates. Do not enable hosted gates or integrate app code to main behind predecessor release gates.
